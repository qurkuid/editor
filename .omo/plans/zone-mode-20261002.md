# Zone quick-view button — implementation contract

## Decision

- Add a standalone text button immediately before `LevelModeToggle` in `CommunityViewerToolbarRight` (`apps/editor/components/viewer-toolbar.tsx`). The visible Korean label is `존`; the tooltip/accessibility label is `존 보기`.
- Treat it as a toggle over the existing `useEditor.structureLayer`: `zones` means pressed, `elements` means released. This works in 3D, 2D, and split view through the existing 3D `ZoneSystem`, 2D zone floor-plan geometry, shared `selection.zoneId`, and existing zone inspector.
- Do **not** add a third `FloorplanMode`, persistence key, renderer, panel, or zone store. Default/Expert annotations and their per-project persistence remain unchanged.

## Exact change

1. `apps/editor/components/viewer-toolbar.tsx`
   - Add a small `ZoneViewToggle` rendered directly before `<LevelModeToggle />`.
   - Use `aria-pressed={structureLayer === 'zones'}` and the toolbar's existing active/inactive styling. Render text only, as requested.
   - Keep one exported command in this file for the button and focused test:
     - First emit `emitter.emit('tool:cancel')` so an in-progress placement, move, or floor-plan draft rolls back through the established cancel contract, then clear any remaining `movingNode` with `setMovingNode(null)`.
     - Enter: `setMode('select')`, `setPhase('structure')`, then `setStructureLayer('zones')`. Setting Select first prevents an existing build mode from arming the zone creation tool; this button is for inspection.
     - Exit: `setMode('select')`, then `setStructureLayer('elements')`.
     - Rely on `setStructureLayer` to clear incompatible `selectedIds` and `zoneId`. Do not mutate scene nodes.
   - Derive pressed state from the store; add no local or persisted state.
2. `packages/editor/src/i18n/dictionary/viewer-chrome.ts`
   - Add the visible `존`/`Zones` label and `존 보기`/`Zone view` accessibility/tooltip text.
3. `apps/editor/components/viewer-toolbar.test.ts`
   - Exercise the exported toggle command against the real editor/viewer stores: entering from an active structure build emits cancel, ends in `structure + select + zones`, clears the active tool/selection, and leaves `useFloorplanMode.mode` unchanged; toggling again ends in `select + elements` and clears a selected zone.

No modeling-agent manual update is required: this exposes an existing presentation/selection path and adds no modeling operation, schema, MCP capability, unit rule, or AI control.

## Acceptance

- Desktop: at `http://localhost:3002/editor/expert-room-qa`, the `존` button is directly left of the current level display button (`적층`/`분해`/`단독`). Its pressed styling and `aria-pressed` track zone view.
- Entering from Select, Build, or an unfinished draft cancels transient work without committing a node, switches to zone inspection, and shows the current level's colored zone fills/labels.
- Clicking a room zone in 2D, or its existing label affordance in 3D, selects `selection.zoneId` and opens the existing room/zone inspector with name, number, ceiling height, area, perimeter, and available quantities.
- Pressing `존` again hides the zone fills, returns to element selection, and closes stale zone inspection by clearing `zoneId`.
- Default/Expert floor-plan mode, annotation settings, view mode, level mode, and saved scene data do not change when the button is toggled.
- Mobile: at a 390 px-wide viewport, the same button remains visible immediately before the level button, is tappable, and does not clip or overlap either toolbar group. If the existing combined toolbar already overflows, adjust only toolbar spacing needed to keep this requested control reachable; do not create a second mobile-only mode.
