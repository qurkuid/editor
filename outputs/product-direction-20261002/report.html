구체적인 근거와 완료 조건

1. 자동 모델링을 다시 실행해도 수정·마감이 남아야 합니다

코드에서 확인한 교체 동작 현재 에디터 내 자동 모델링은 같은 층·같은 도면의 apt-vector 요소와 해당 자동 바닥·천장을 제거하고 새 요소를 생성합니다. 수동·무관한 요소는 보존하지만, 자동 생성된 벽을 나중에 사람이 고친 경우를 구분해 병합하지 않습니다. 그 벽의 변경과 마감도 교체될 수 있습니다.

최소 보완은 재생성 전 변경 대상 안내와 사본 생성입니다. 이어서 원본 추출값 대비 사용자가 수정한 요소를 구분하고, 기존 유지·새 결과 채택을 선택하게 해야 합니다. 장면 저장 버전 충돌 보호는 이미 있지만, 이 재분석 병합과는 별개입니다.

완료 조건: 벽 이동·벽지 변경·수동 벽 추가 후 재분석 → 보호 대상 표시 → 변경 선택 적용 → 유지하기로 한 요소 보존 → 한 번 Undo로 원상 복원.

apps/editor/components/apt-search-panel.tsx:134–169 · apps/editor/lib/apt-import-frame.ts:65–115 · apps/editor/components/scene-loader.tsx:246–353. 이 검토에서 원본 장면을 실제 재생성하지 않았습니다.

2. 일부만 전달된 견적을 화면에서 구분해야 합니다

확인된 화면 처리 누락 견적 전송은 문서를 만든 뒤 항목을 각각 추가합니다. 일부 항목이 실패하면 {ok:true,itemCount:1,failedItems:1}처럼 반환합니다. 이 경우는 기존 테스트에도 있지만, 통계 화면은 failedItems를 읽지 않고 성공 항목 수만 보여줍니다.

먼저 성공·실패 건수와 견적 열기 링크를 표시하고, 실패 항목을 식별해 복구해야 합니다. 이후 장면에 전송한 견적 ID·장면 버전·물량 사본을 연결하면 중복 생성 예방과 변경 전후 비교가 가능합니다. 전체 거래를 새로 설계할 필요 없이 현재 전송 함수와 응답을 확장할 수 있습니다.

완료 조건: 두 항목 중 하나가 실패한 응답 → 부분 완료 표시와 실패 항목 확인 → 같은 견적의 누락 항목만 복구 → 재시도 시 성공 항목 중복 없음.

apps/editor/lib/estimate-submit.ts:105–146 · estimate-submit.test.ts:120–134 · apps/editor/components/stats-tab.tsx:247–257. 모의 전송 테스트와 화면 코드의 대조 결과이며, 실제 고객 견적을 생성하지 않았습니다.

3. “다른 치수 유지”의 범위를 더 명확하게 만들어야 합니다

현재 기능의 범위 치수 편집은 연결·개구부 검증과 선택 치수선의 다른 구간 유지를 지원합니다. 그러나 벽을 공유하는 다른 치수선까지 모두 고정하는 기능은 아닙니다. 현재 팝오버는 목표값·고정 끝·변경 구간을 입력하고 적용하는 흐름입니다.

기존 계산 계획을 활용해 적용 전 이동할 벽과 바뀔 치수를 강조하고 전후 값을 보여주는 것이 먼저입니다. 다음으로 사용자가 중요한 치수를 잠그고, 서로 양립할 수 없는 고정 조건은 수정 전에 이유와 함께 거부하도록 보완합니다.

완료 조건: 거실 폭을 변경할 때 주방 치수를 잠금 → 유지 가능하면 보존 → 불가능하면 충돌 치수와 이유 표시 → 미리보기 취소 시 장면 변경 없음.

4. 열린 거실·주방은 사용자가 경계를 확정할 수 있어야 합니다

기존 검수의 잔여 한계 8개 도면의 108개 공간 기준점 대응 검사는 통과했습니다. 같은 보고서는 벽 없는 거실·부엌의 존 경계가 글자 위치를 기준으로 한 근사 경계이고 정확한 설계 면적선을 보장하지 않는다고 밝힙니다. 기준점 통과를 전체 경계 정확도로 해석해서는 안 됩니다.

존 경계에 확정·근사·확인 필요 상태를 보여주고, 기존 존 편집으로 경계를 보정해 확정하는 흐름을 연결해야 합니다. 확정되지 않은 공간의 면적은 견적·자재 적용 화면에서도 그 상태가 이어져야 합니다.

완료 조건: 열린 거실·주방 경계를 보정·확정 → 면적 합계와 방별 바닥 영역 일치 → 한 방의 마감 변경이 옆방을 바꾸지 않음 → 저장 후 상태 유지.

5. 방별 마감 선택을 방별 물량과 금액으로 이어야 합니다

누락된 귀속 정보 물량은 자재별로 집계되고 원본 노드 ID를 보유합니다. 하지만 TakeoffLine에는 방 ID·방 이름·방별 소계가 없습니다. 마감의 INTM 자재 연결과 산술은 이미 있으므로, 필요한 것은 방·벽면 귀속과 설명입니다.

선택한 방의 벽·바닥 순면적, 문·창 공제, 구매 단위·손실률, 미매칭 자재를 함께 보여주고 항목을 클릭하면 해당 면을 강조해야 합니다. 공유 벽은 면별 귀속을 유지해 양쪽 방에 전체 벽을 중복 계산하지 않아야 합니다.

완료 조건: 거실·주방에서 같은 자재 사용 → 방별 물량 소계 확인 → 두 방 합계가 전체 집계와 일치 → 견적 항목에서 원본 방·면으로 돌아갈 수 있음.

6. 템플릿은 다른 구조의 집에서도 안전하게 재사용돼야 합니다

현재 구현 중인 코드의 한계 방·집 템플릿 저장과 적용 로직이 있습니다. 집 템플릿 엔진은 방별 벽면 연결 정보를 받을 수 있지만, 집 전체 연결 화면은 방 연결과 벽 재질 통일만 전달합니다. 다른 집에서 포인트 벽을 유지하려면 방 안의 목표 벽면도 지정할 수 있어야 합니다.

저장은 현재 브라우저 로컬 저장소입니다. 우선 템플릿 내보내기·가져오기로 백업과 이동을 지원하고, 실제 직원 공동 사용이 필요할 때 회사별 저장을 붙이는 순서가 적절합니다. 또한 현재 집 저장 화면은 모든 방의 완성을 요구하므로, 저장된 방 조합을 선택·조립하는 흐름은 별도로 검토할 가치가 있습니다.

완료 조건: A집의 포인트 벽 포함 조합을 B집에 적용 → 방 연결·포인트 벽 지정 → 반대편 벽 유지 → 전체 적용 한 번 Undo → 템플릿을 다른 브라우저로 이동.

7. 기능 단위 검수를 실제 업무 시나리오로 연결해야 합니다

마감 템플릿의 단위 검증은 통과했지만, 이것만으로 운영에서 방 선택·카탈로그·적용·저장·재접속이 모두 완성됐다고 볼 수 없습니다. 최근에는 로컬 수정과 운영 반영이 달라 사용자가 반복해서 배포를 요청했습니다.

대표 도면 하나에서 도면 반전 → 자동 생성 → 치수 보정 → 방별 재질 → 집 템플릿 → 물량 확인 → 저장·재접속 → Undo를 이어서 검수해야 합니다. 앱 버전·추출기 버전·장면 생성 버전을 구분해 새로고침으로 해결되는지, 재분석이 필요한지도 알려줘야 합니다.

완료 조건: 위 시나리오를 별도 검수 장면에서 2D·3D로 실행하고 저장 그래프·물량·Undo·콘솔을 확인. INTM 전송은 모의 테스트와 실제 전송 증거를 구분.

전체 배포 검수 기록 · 현재 미커밋 마감·템플릿 코드와 테스트. 이번 검토에서 새 배포를 하지 않았습니다.

8. 방 중심의 작업 화면과 AI 실행을 같은 계약으로 묶어야 합니다

후속 제품 개선 운영 화면에서 전문가 치수·벽 편집은 보이지만, 도면·표시 설정·모델링·도장·통계가 여러 위치에 나뉩니다. 방을 선택한 상태에서 치수·벽면·바닥·물량으로 이동하고 선택 맥락을 유지하면 기능을 찾는 비용이 줄어듭니다.
